# kazakiri 改善点・追加機能の提案（調査メモ）

最終更新：2026-11-18（v0.14.0 時点の調査。「おすすめの進め方」の 1・2 を実装）

目的：EmEditor を参考に、**大きなファイルでも高速に動く**テキストエディタ。
このファイルは調査結果の記録。作業で状況が変わったら、状態の欄（☐ 未着手 / ◐ 進行中 / ☑ 完了）と更新日を直す。

## 現状のまとめ

- v0.14.0、約 2.8 万行の Rust。`kazakiri-core`（コア）、`kazakiri-win`（Win32 + Direct2D）、`kazakiri-cli`。
- 大きなファイル：メモリマップ + 疎な行索引、ピーステーブル、外部ソート、分割・結合、巨大な 1 行の窓描画まで実装済み。
  計測値は目標を大きく上回る（3GB を 0.9ms で表示、全行索引 0.21 秒、すべて置換 840 万件 1.6 秒）。
- 日常機能：タブ、GREP、差分、マルチカーソル、矩形選択、構文色分け、Markdown プレビュー、バックアップ・自動保存、キー割り当てなど、EmEditor の主要機能はほぼ揃っている。
- 直近の開発は UI の見た目調整に集中。性能面の機能追加は v0.11 以降ほぼ止まっている。
- テスト：コア 75 + 6、win 16。

## マクロ（Rhai）の検討メモ（未実装。物足りなくなったときに本格的に作る）

いまの「操作の記録と再生」では足りなくなったとき（条件分岐・繰り返し・変数・文字列加工・複数のマクロの管理が必要になったとき）に、スクリプト言語を組み込む。その下調べと方針の案。

### 言語の候補と、Rhai を第一候補にする理由
| 候補 | 利点 | 欠点 |
|---|---|---|
| **Rhai**（第一候補） | Rust だけで書かれていて、C のビルドが要らない（CI・配布が楽）。小さい（数百 KB）。組み込み向けで、安全（既定ではファイル・ネットワークに触れない）。Rust の関数を数行で登録できる。構文が Rust/JS に近い。操作数の上限・実行時間の打ち切り（`on_progress`）が標準である | 速度は Lua より遅い（ただし、重い処理は Rust の関数に任せる設計にすれば問題にならない）。日本語の情報は少ない |
| Lua（`mlua`） | 速い、情報が多い、EmEditor 以外のエディタでも定番 | C のライブラリを組み込むため、ビルドと配布が複雑になる（Windows/Linux の CI、静的リンク） |
| JavaScript（`boa` など） | EmEditor・VS Code ユーザーに馴染みがある | 大きい、遅い、組み込みの成熟度が低い |

### 設計の案
- **実行の場所**：UI スレッドで、手順ごとに画面へ制御を返す（いまの `macro_run` の方式を拡張）。長い処理は、検索・置換・並べ替えなど既存の別スレッドの処理を呼び、完了を待つ（`await` 相当）。スクリプトからは同期の関数に見せ、実行器が完了を待つ形にする
- **API の範囲（最初）**：`doc.text_of(a, b)`・`doc.insert(pos, s)`・`doc.replace(a, b, s)`・`doc.delete(a, b)`、`sel.get()`・`sel.set(a, b)`、`line.count()`・`line.text(n)`・`line.start(n)`、`find(text, opts)`・`find_all(...)`・`replace_all(find, repl, opts)`、`cmd("line_duplicate")`（キー割り当てと同じコマンド名で、メニューの任意のコマンドを呼ぶ）、`msg(s)`・`input(prompt)`・`confirm(s)`
- **大きなファイルでの安全策**：全文を文字列で渡す関数は作らない（範囲を指定して取り出す関数だけ）。範囲の大きさに上限（既定 64MB）。`for` の回数・実行時間の上限と、Esc での中止を必ず入れる
- **取り消し**：スクリプト 1 回の実行を、1 回の Undo にまとめる（`Editor` にトランザクション〈取り消し単位の開始・終了〉を足す）。これはいまの記録・再生にも効く
- **ファイル構成**：`%APPDATA%\kazakiri\macros\*.rhai`。先頭のコメントに名前と説明を書く。メニュー（編集 → マクロ）に一覧を出し、キー割り当て（keys.ini）にも `macro:名前` で割り当てられる
- **記録から台本へ**：いまの記録（`macro.txt`）を、Rhai の台本として書き出す（`type("abc")`・`key("Down")`・`cmd("...")`・`find("...")`）。記録 → 書き出し → 編集、の順で覚えられる
- **セキュリティ**：既定では、ファイル・プロセス・ネットワークへの関数を登録しない。必要なら、設定で「ファイル読み書きを許可」を別に用意し、許可するフォルダを限る。他人から受け取った台本は、実行前に内容を表示して確認する
- **テスト**：台本の実行を、画面なしで試せるよう、実行器を `kazakiri-core` 側に置き（`Editor` と `Document` だけに依存）、UI は薄い層にする。大きなファイルでの性能は `perf_guard` に項目を足す

### いまの実装からの移行
- 手順の型（`Step`）は、Rhai の関数呼び出しに 1 対 1 で対応させられる。記録済みの `macro.txt` は、そのまま読み込める形で残す（互換）
- 「置換」を記録できない制限は、実行器が非同期の完了を待てるようになれば解消する
