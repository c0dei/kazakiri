## 目的と決定事項
- 高速・省メモリが方針。GUI フレームワークは使わず、**Win32 の標準部品**（comctl32）を使う。描画は今まで通り Direct2D／GDI。
- 自前描画で似せていた部品を、本物の標準部品に替える（読み上げ・キー操作・DPI・ダーク対応を OS に任せる）。
- 対象は **設定ダイアログの全部品** と **本体画面**（タイトルバー・メニュー・タブ・ツールバー・モードバー・検索バー・ステータスバー）。
- **本文（エディタ領域）は自前描画のまま**（数 GB を速く開くため）。スクロールバーも今のまま。
- ダークは `SetWindowTheme(h, "DarkMode_Explorer")`（入力欄は `DarkMode_CFD`）。`dark.rs` に既存の処理あり。
- 決定: アクセントカラーのドロップダウンは、色の丸を付ける（コンボの項目だけ自前描画。部品は本物）。フォントは一覧から選ぶ `CBS_DROPDOWNLIST`。
- 本体のタイトルバーは標準に戻す（モックの通り）。タブの × とドラッグ並べ替えは、標準では付かないので、フェーズ 6 で自前の処理を足す（中クリックで閉じる、ドラッグで並べ替え）。

## 確認の方法
- この環境（Linux）で: `cargo check --target x86_64-pc-windows-gnu -p kazakiri-win` と `cargo clippy --target x86_64-pc-windows-gnu -p kazakiri-win`（警告ゼロ）。コアのテストは `cargo test -p kazakiri-core -p kazakiri-cli`。**`kazakiri-win` のテストは Windows でしか動かない**（Linux の `cargo test --workspace` は win で失敗するのが正常）。Windows のテストは、ユーザーの実機か CI で。
- 見た目・ダーク・DPI・キーボード・ナレーターは **Windows 実機でユーザーが確認**（スクリーンショットをもらって直す）。この環境では確認できない。

## 技術的なリスク
1. 標準部品は親の背景を借りて自分の背景にする。カードを `WM_PAINT` で描くと、部品の周りがカード色にならない → カード描画を `WM_ERASEBKGND` 側（GDI 版 `gdi_cards` を流用）に寄せる。
2. ダークで、チェックボックス・コンボの文字色が黒のままになることがある → `NM_CUSTOMDRAW` か `WM_CTLCOLOR*` で合わせる。
3. 入力付きコンボは、再配置のたびに全選択になる（HANDOFF）→ `CBS_DROPDOWNLIST` にして避ける。
4. 標準タイトルバーに戻すと、`caption.rs`（自前のタイトルバー）、`DwmSetWindowAttribute` まわり、全幅描画（`full_w`）の前提が変わる。

### フェーズ 6: タブの × とドラッグ並べ替え（必須。秀丸・EmEditor と同じく、あって当然の操作）
標準の SysTabControl32 には × もドラッグ並べ替えもないので、タブコントロールを**サブクラス化**して足す（フェーズ 5 でタブを替えた直後にやる）。既存の並べ替え・閉じるの処理は `tabs.rs` にあるので、見た目と入力だけを新しい部品へ付け替え、タブの順序・未保存の確認はアプリ側（今のモデル）を使い続ける。
- 設計（先に決めたこと）:
  - **× の描画**: タブコントロールの `NM_CUSTOMDRAW`（comctl6 のタブが対応）で、各タブの右端に × を描く。マウスが乗ったタブだけ濃く、× の上では丸い背景。文字は `TCM_SETPADDING` で右に余白を取る。ダークの配色もここで描く（標準のタブはダークにならない）。
  - **× のクリック**: サブクラスの `WM_LBUTTONUP`。`TCM_HITTEST` ＋ `TCM_GETITEMRECT` で × の矩形に入っているか判定し、`WM_COMMAND` 相当の「タブを閉じる」へ（未保存なら今まで通りの確認）。
  - **中クリックで閉じる**: `WM_MBUTTONUP`。Ctrl+W は既存のまま。
  - **ドラッグで並べ替え**: `WM_LBUTTONDOWN` で開始位置を覚え、数 px 動いたら `SetCapture`。`WM_MOUSEMOVE` で `TCM_HITTEST` したタブへ、ドラッグ中のタブを入れ替える（モデルを並べ替えて、タブの項目も入れ替える）。ドラッグ中は挿入位置の線か、動くタブの強調。`WM_LBUTTONUP` / `WM_CAPTURECHANGED` / Esc で終了・取消。
  - **はみ出し**: タブが多いときは `TCS_SINGLELINE` のスクロール矢印（標準）。ドラッグ中にタブバーの端へ寄せたら自動スクロール。
  - **未保存の印 `*` とファイル名の省略**: タブの文字を更新するたびに `TCM_SETITEM`。長い名前は省略（`…`）。ツールチップに全体のパス。
  - **タブの幅**: 内容の幅に合わせ、最小幅（`TCM_SETMINTABWIDTH`）を設ける。

## メモ（作業中に分かったこと）
- **実機で分かったこと（1 回目）**: チェックボックスの部品が、全体に既定の灰色（#f0f0f0）の背景を塗って、カードの説明文を隠した。→ 部品を題の行だけの高さ（20 DIP）にし、背景は `WM_CTLCOLORBTN` と `NM_CUSTOMDRAW`（`CDDS_PREPAINT` で `FillRect`）でカードと同じ色に塗る。標準部品は「透明」にせず「親の色で塗る」のが確実。箱の色（ダークで暗い箱、アクセント色のチェック）と文字色は、実機で意図どおりだった。
- CI の Linux ジョブの `diff::tests::options_ignore_space_and_case` が、1 回だけ落ちた（コアは未変更。手元の release では 3 回とも通る。ばらつきのあるテストの疑い。再発したら調べる）。
- 実機で見てほしい点（チェックボックス）: ①箱の周りがカード色か（白い下地が出ないか）②ダークで題の文字が白いか③題と説明の左端がそろっているか（ずれたら `TOGGLE_INDENT`）④Tab・Space・クリックで切り替わり、保存まで反映されないか⑤リサイズ・スクロール
