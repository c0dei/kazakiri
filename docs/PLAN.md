# kazakiri 開発計画

## 前提

- 対象 OS：Windows のみ（10 / 11）
- 主な用途：ログ、CSV、TSV、txt。大きさは数GB
- 言語：Rust。UI は Win32 + Direct2D/DirectWrite（ネイティブ）

## 参考にしたエディタ

| | EmEditor | 秀丸エディタ | サクラエディタ |
|---|---|---|---|
| 形態 | サブスク（無料版は大容量・マクロ等なし） | 買い切りシェアウェア | 無料 OSS |
| 大容量 | 最大16TB。分割・結合、Large File Controller | 速いが巨大 DB 出力では重いとの声 | 数百MB程度まで |
| 強み | 速度、CSV 列表示・ソート、並列検索、文字コード判定 | マクロ、日本語処理、複数ファイル一括置換 | GREP / GREP 置換、矩形選択、文字コード変換 |

取り入れる UI：タブ、行番号、ステータスバー（文字コード・改行・位置）、矩形選択、
インクリメンタル検索とハイライト、GREP 結果一覧、文字コード指定で開き直す、空白・改行の可視化。

## 設計の柱

1. **メモリマップ**：ファイルを読み込まない。アプリ固有メモリは数MB
2. **疎な行インデックス**：256 行ごとの開始位置だけ記録。8MB チャンクを全コアで並列走査し、
   先頭から終わった分だけ即利用（開いた瞬間に表示）
3. **見えている行だけ描画**：ファイルサイズに関係なく描画コストは一定
4. **（編集時）ピーステーブル**：元ファイルは読み取り専用のまま、変更差分だけを持つ
5. **保存は一時ファイル → 置き換え**：マップ中のファイルを直接上書きしない

## 目標値

| 項目 | 目標 | v0.1 の実測（Linux、キャッシュ済） |
|---|---|---|
| 1GB を開いて先頭表示 | 0.1 秒以内 | 0.01 秒 |
| 3GB の全行索引 | 2 秒以内（SSD） | 0.21 秒 |
| 任意行へのジャンプ | 1 ms 以内 | 0.01 ms |
| 全文検索 | 1 GB/秒以上 | 3〜6 GB/秒 |
| 10GB 開いた時のアプリ固有メモリ | 200 MB 以下 | 数 MB 規模 |

## 既知の注意点

- メモリマップ中のファイルを他プロセスが切り詰めることは Windows が拒否するため安全。
  追記は可能だが、マップ時点の長さまでしか見えない（再読み込みで反映：フェーズ1.5）
- 索引作成中は総行数が「約」表示（推定値）。索引が届いていない位置へは移動できない
- Wine では DirectWrite の `HitTestTextRange` / `HitTestPoint` が未実装のため、文字列幅から位置を求める代替処理を入れている
